Set up NanoProteinLM AutoResearch with the Karpathy-style sequential search, then hand it over to the user. Run everything on this machine, which should be the GPU compute node, never a login node.

First, ask the user these questions in one message, showing each default. Use the default for anything the user accepts or skips.

1. Workspace folder. Default: ./nano-protein-autoresearch
2. Data and output folders. Default: DATA_ROOT=<workspace>/data (about 20 GB for the default 30 training shards) and OUTPUT_ROOT=<workspace>/outputs.
3. Coding agent that will run the search, and the command that starts it. Default: the same agent as you, started in the mode the user uses for long unattended runs. Examples: Codex with `codex --approve-for-me`, or Claude Code with `claude`.
4. Task and program. Default: tasks/171m-validation-loss.md with autoresearch/karpathy_ar_reward_gate.md. Alternatives: tasks/171m-p-at-l.md optimizes contact P@L, and autoresearch/karpathy_ar_agent_gate.md lets the agent decide what to keep.
5. Round limit. Default: the full 72-round allowance. Alternative: a short qualification run with the baseline and one candidate.
6. tmux session name. Default: nanoprotein-ar

Then, using the answers:

A. Check that nvidia-smi shows four matching H100 or L40S GPUs and that tmux, git, npx (Node.js) and uv >=0.11.31,<0.12 are installed. If anything is missing, tell the user and stop.

B. Install the loop skill for the chosen agent, naming it with -a (for example codex or claude-code):
   npx skills add Lumin-Science/Nano-AutoResearch-Skills --skill ar-loop-n-sleep -g -a <agent> -y

C. Clone only the release commit into the workspace folder and remove the remote:
   git clone --depth 1 --single-branch --no-tags --branch autoresearch-v0 https://github.com/Lumin-Science/Nano-ProteinLM.git <workspace>
   cd <workspace> && git remote remove origin
   If HTTPS asks for credentials, use git@github.com:Lumin-Science/Nano-ProteinLM.git instead.

D. If the user changed the data or output folder, write DATA_ROOT=<path> and OUTPUT_ROOT=<path> to <workspace>/.env. Then run `bash runs/setup.sh` in the workspace and let it finish; it installs the environment and downloads and verifies the data.

E. Start a detached tmux session with the chosen name in the workspace, running the chosen agent command. If the agent asks to trust the folder, accept. If it asks for anything else, such as signing in, stop and tell the user. Once its input box is ready, type this prompt into it with `tmux send-keys -l`, single-quoted, and do not press Enter:
   Use the ar-loop-n-sleep skill. Read <task> and <program>. Use the allocated four GPUs. Run sequential AutoResearch for <round limit>, following the program, then stop without another wakeup.

F. Tell the user to run `tmux attach -t <session>` and press Enter to start the search. Do not start the research yourself.
